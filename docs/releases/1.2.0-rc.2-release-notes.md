# Quantara 1.2.0-rc.2 release notes

Build number: `121`

This release candidate fixes the two blockers found during the first physical Samsung canary:

1. One malformed `AVAXUSDT|15m` REST candle no longer aborts the complete public realtime universe.
2. A zero-position Local Live session in `managingOnly` no longer traps the UI with no safe way to re-enable entries.

## Realtime behavior

- Recent bootstrap rows are decoded independently.
- Invalid OHLC is never coerced, repaired or admitted to strategy history.
- Up to eight malformed rows may be discarded from the bounded 200-row recent-history response.
- The production runtime asks for 120 closed candles, preserving reserve history after bounded row rejection.
- A stream that still cannot bootstrap is quarantined; healthy streams connect and remain usable.
- If every configured stream fails, startup still fails closed.
- The health strip shows healthy/configured and quarantined stream counts and uses `Degraded live monitoring` when appropriate.

## Local Live behavior

- `managingOnly` continues to block new entries by default.
- When there are no open managed positions, an explicit `Resume entries` action is shown.
- Resume repeats affordability preflight, foreground-service startup, API credential handoff and all real-money confirmations.
- Entry authority is never restored automatically after restart, service recovery or market-data recovery.
- If a protected position is open, Resume remains unavailable and Quantara continues management-only reconciliation.

## Safety boundary

No private API permission, withdrawal/transfer capability, position count, sizing logic, leverage/risk ceiling, stop-loss rule or take-profit protection requirement was expanded.
