# Quantara 1.2.0-rc.1 migration and recovery

## Upgrade path

1. Export or note any settings that are important before installing the RC.
2. Install the Android RC over the existing alpha package to exercise the upgrade path.
3. Launch the app and confirm persisted watchlist, language, theme, Journal and Signal Inbox state are readable.
4. Confirm Local Live is disarmed even when previous non-sensitive settings are restored.
5. Keep the previous APK available until the RC test is accepted.

## Data compatibility

- Existing opportunity state and settings continue to use bounded SharedPreferences-backed stores.
- Candidate audit uses primary and backup ledgers. A corrupt primary ledger is recovered from the backup when possible.
- Unknown or malformed persisted entries are rejected rather than interpreted permissively.
- No secret is migrated into repository files or public realtime state.

## Recovery

If the application cannot start after an in-place upgrade:

1. Capture the Android launch diagnostics and device logs before clearing data.
2. Reinstall the previous test APK to confirm whether the problem is release-specific.
3. If necessary, clear only the app's local alpha data and reconfigure the watchlist; this removes local Journal/Signal Inbox state.
4. Do not copy API secrets into issue comments or diagnostic bundles.

## Rollback boundary

The RC does not modify `main` or the Stable package. Rolling back the test installation does not require a server or database migration. Stable promotion remains a separate reviewed PR after physical test acceptance.
