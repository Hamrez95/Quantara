# چک‌لیست پذیرش فیزیکی Quantara 0.13.1-rc.1

این نسخه یک **Release Candidate** برای بررسی روی دستگاه واقعی است و تا تکمیل این چک‌لیست نباید با برچسب Stable یا Live-ready منتشر شود.

## مرز ایمنی

- اتصال حساب به‌تنهایی نباید هیچ سفارشی ثبت کند.
- اجرای محلی فقط پس از Start صریح کاربر مجاز است.
- برای تست‌های این سند نیازی به ثبت سفارش واقعی نیست.
- دسترسی برداشت/انتقال، مارتینگل، میانگین کم‌کردن، افزایش استاپ و Cross Margin خارج از محدوده‌اند.
- Server Auto باید قفل و غیرقابل اجرا باقی بماند.

## مشخصات دستگاه

- نسخه Android / One UI: ................................
- نصب تمیز یا ارتقا روی نسخه قبلی: ................................
- زمان شروع تست: ................................

## A. نصب و راه‌اندازی

- [ ] APK بدون حذف داده‌های نسخه قبلی، به‌صورت Upgrade نصب می‌شود.
- [ ] Cold Start موفق است و برنامه بلافاصله بسته نمی‌شود.
- [ ] Warm Start و بازگشت از Recent Apps موفق است.
- [ ] زبان فارسی، RTL، فونت و نوار ناوبری درست نمایش داده می‌شوند.
- [ ] تغییر Light/Dark باعث خطا یا از دست رفتن صفحه فعلی نمی‌شود.

## B. رگرسیون سطح خاکستری Setups

این مسیرها را حداقل سه بار تکرار کنید:

1. Radar → Setups
2. Analysis → Setups
3. Watchlist → Setups
4. Auto Trade → Setups
5. اسکرول تا انتهای لیست و بازگشت به بالا

- [ ] سطح خاکستری بسیار بلند یا اسکرول بی‌انتها دیده نمی‌شود.
- [ ] هیچ کارت خراب کل صفحه را از کار نمی‌اندازد.
- [ ] در صورت خطای یک کارت، Recovery Card محدود با کد `Q-UI-001` دیده می‌شود.
- [ ] NaN، Infinity یا متن عددی خراب در UI دیده نمی‌شود.

## C. صندوق پیشنهادها و چارت دقیق

برای یک پیشنهاد 15m، یک پیشنهاد 1h و یک پیشنهاد 4h:

- [ ] از Signal Inbox روی «دیدن تحلیل» بزنید.
- [ ] نماد دقیق پیشنهاد خودکار انتخاب می‌شود.
- [ ] تایم‌فریم دقیق پیشنهاد خودکار انتخاب می‌شود.
- [ ] Entry، SL و TP1/TP2/TP3 مربوط به همان پیشنهاد روی چارت هستند.
- [ ] برگشت به Signal Inbox، وضعیت قبلی و اسکرول را حفظ می‌کند.
- [ ] تغییر دستی نماد/تایم‌فریم، Overlay تاریخی قبلی را پاک می‌کند.
- [ ] برای زمینه نامعتبر یا حذف‌شده، پیام قابل بازیابی نمایش داده می‌شود و چارت اشتباه باز نمی‌شود.

## D. سرنوشت فرضی سیگنال

- [ ] Taken/Not Taken فقط متادیتای کاربر است و پایش فرضی را متوقف نمی‌کند.
- [ ] سیگنال لمس‌نشده بعد از پایان اعتبار، Expired Untriggered می‌شود.
- [ ] برخورد Entry سپس TP1/TP2/TP3 در ژورنال ثبت می‌شود.
- [ ] برخورد استاپ با نتیجه و درصد فرضی مشخص می‌شود.
- [ ] بعد از TP1 یا TP2 و سپس استاپ، سود بخش‌های 35٪ و 35٪ حفظ می‌شود و فقط حجم باقی‌مانده استاپ می‌خورد.
- [ ] نتیجه فرضی با P/L واقعی حساب Bitunix مخلوط نشده است.
- [ ] حذف نماد از Watchlist باعث حذف یا توقف ژورنال باز نمی‌شود.
- [ ] پس از بستن و بازکردن برنامه، ژورنال و نتیجه‌ها باقی می‌مانند.

## E. پیش‌بررسی سرمایه اجرای محلی

بدون ثبت سفارش واقعی و با موجودی بسیار کم:

- [ ] Start به‌جای سکوت، موجودی قابل استفاده را نشان می‌دهد.
- [ ] حداقل تقریبی لازم برای ارزان‌ترین نماد انتخاب‌شده نمایش داده می‌شود.
- [ ] مقدار کسری سرمایه نمایش داده می‌شود.
- [ ] توضیح داده می‌شود که فاصله استاپ، ریسک، هزینه و Slippage ممکن است سرمایه بیشتری بخواهند.
- [ ] هیچ قانون حداقل حجم، SL/TP یا ریسک برای اجبار به معامله ضعیف نمی‌شود.
- [ ] در صورت وجود پوزیشن قبلی، سرویس امکان Reconcile آن را دارد اما پوزیشن دوم باز نمی‌کند.

## F. پس‌زمینه و بازیابی

- [ ] با رفتن برنامه به پس‌زمینه، UI بعد از بازگشت سالم است.
- [ ] بعد از قطع و وصل اینترنت، داده قدیمی به‌عنوان داده تازه نمایش داده نمی‌شود.
- [ ] Force Stop یا Reboot باعث Auto-arm شدن اجرای محلی نمی‌شود.
- [ ] تنظیم انتخاب‌شده حفظ می‌شود ولی Start باید دوباره صریح انجام شود.
- [ ] اعلان Foreground فقط هنگام اجرای محلی فعال دیده می‌شود.

## G. تست فشار کوتاه

- [ ] حداقل 30 بار بین Radar، Setups، Analysis، Watchlist، Auto Trade و Profile جابه‌جا شوید.
- [ ] حداقل 10 بار نماد و تایم‌فریم را سریع تغییر دهید.
- [ ] برنامه Crash، Freeze، Overflow یا اسکرول غیرعادی ندارد.
- [ ] زمان پاسخ UI قابل قبول است و لمس‌های تکراری باعث عملیات تکراری نمی‌شوند.

## نتیجه

- [ ] PASS — آماده ادغام در شاخه کاندید انتشار
- [ ] FAIL — نیازمند اصلاح

### گزارش خطا

برای هر FAIL ثبت شود:

- مرحله و شماره بند
- اسکرین‌شات یا ویدئو
- زمان تقریبی رخداد
- نماد و تایم‌فریم
- وضعیت اینترنت
- نصب تمیز یا Upgrade
- متن خطا یا کد Recovery

فقط در صورت عبور کامل بخش‌های A تا G:

1. PR اصلاحات در شاخه کاندید ادغام شود.
2. CI کامل روی SHA نهایی دوباره اجرا شود.
3. APK و PWA نهایی با SHA-256 منتشر شوند.
4. نسخه ابتدا با برچسب `0.13.1-rc.1` منتشر شود.
5. پس از یک دور استفاده بدون P0/P1، برچسب Stable برای قابلیت‌های مانیتورینگ/تحلیل بررسی شود؛ اجرای واقعی همچنان Canary و Opt-in باقی بماند.
